# Skill 场景式自检

本表是主Agent对指令和产物的场景审查，不是独立Agent前向测试，也不声称已通过真实用户研究。

| 输入情境 | 合理行为与验收点 | 本包对应 |
|---|---|---|
| 只有海港轮廓，没有尺度和移动 | 先问移动/镜头、比例尺与保留范围、最高目标/平台；研究可继续，街宽与ETA不冻结 | 输入审计与询问规则 |
| 用户明确要测试范例 | 自主设定前提，不把原创设定冒充用户世界观，不反复询问 | A01–04、F01–06、原创世界观 |
| 世界观说禁止电力，参考图里有电车 | 记录冲突，保留世界观，换交通技术或问是否允许变更；不从图片推翻硬设定 | workflow目标冲突和intake |
| 用蜘蛛侠案例规划纯步行城 | 迁移实验方法，不迁移街宽、摆荡点间距和工期 | GDC映射与移动验证 |
| 用户只问“改一下POI名字” | 保留其他规划，不重新发明历史或强制全部流程 | 工作模式与最小修改 |
| 历史先洪灾后高堤，却有路早于端点 | 报时序错误，修节点成立或道路时期并重跑路线 | 早生道路与未来因果故障测试 |
| 骑行玩家从只允许步行的灯塔街出发 | 报当前模式不可达，给切换步行/入口建议，不忽略权限 | 路线模式测试 |
| 关闭最快坡道 | 重新求合法绕行，时间变长、闭路不再进入路线 | R02回归测试 |
| 文档有净宽计算，设计师想标“白盒通过” | 拒绝据此关闭引擎/玩家P0，保持not_run | X01–04、生产门槛 |
| 附件概括被要求写成“讲者原话” | 保留二次总结属性；要精确引用先回查原视频 | S01–03与来源范围 |
| 只给一堆参考图 | 分析结构/居民/语法/游戏证据；每项写用途和不能照搬，核查许可 | 来源模板与原创图示 |
| 上游灾难被删除或改晚 | 列受影响城区、建筑、POI、道路与实验，不能只改年表 | 稳定ID与变更传播规则 |

在真实项目继续评估时，应让不了解本包设计意图的评估者只持Skill、用户输入与原始资料，检查是否能合理问问题、保留硬设定、输出可追溯决定并拒绝伪实测。
